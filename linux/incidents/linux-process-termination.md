# Linux Incident — Process Termination

## Scenario

A long-running process needs to be stopped sfely during troubleshooting or deployment.

## Symptoms

A process is currently running and needs to be terminated without unnecessarily forcing it.

## Investigation

Find matching processes:

```bash
pgrep -a sleep # provides the pid of the process named sleep
```

```bash
ps -lfp <pid>
```

Check its process status:

```bash
cat /proc/<PID>/status
```

## Resolution

```bash
kill <PID>
```

This sends `SIGTERM` (signal 15).

Verify that the process terminated:

```bash
ps -p <PID>
```

If a process does not respond to SIGTERM and must be forcibly terminated:

```bash
kill -9 <PID>
```

This sends `SIGKILL`.

## Important Difference

| Signal | Number | Behaviour |
|---|---:|---|
| SIGTERM | 15 | Requests graceful termination |
| SIGKILL | 9 | Kernel forcibly terminates process |
| SIGINT | 2 | Interrupt, commonly generated by Ctrl+C |

## Operational Principle

Prefer graceful shutdown:

```text
SIGTERM → grace period → SIGKILL if necessary
```

Applications may use the SIGTERM period to finish requests, close connections, flush logs, and clean up resources.

## Validation

Verify that the PID no longer exists:

```bash
ps -p <PID>
```

or:

```bash
pgrep -a <process-name>
```

## Lessons Learned

- `kill` does not automatically mean force kill.
-  Normal `kill <PID>` sends SIGTERM.
- `kill -9` should generally be a last resort.
- Shell job IDs and Linux PIDs are different concepts.
